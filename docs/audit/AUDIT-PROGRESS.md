## Verified findings so far

Evidence gathered by the lead on 2026-11-15 (all read from code or the SQL Server catalog; since written into reports 02 to 08):

- **Database (catalog of `procurement_qa_msg_verify`, schema V1–V22):** 75 tables (74 + Flyway history), 213 foreign keys, 191 indexes, 94 CHECK constraints, 59 sequences. **117 foreign keys have no unfiltered index led by the FK column** (list in `C:\qa\audit\catalog.txt`). 32 money/quantity columns have no CHECK. 10 tables hold status/kind columns without CHECK. Optimistic `version` column on 18 business tables. Audit tables protected by 3 triggers (append-only, no delete, forward-only). 9 cascading deletes from `purchase_request` and others. RCSI off; collation is whatever the database was created with (README recommends `Latin1_General_100_CI_AS_SC_UTF8`, nothing enforces it).
- **SQL injection:** no user input concatenated into SQL. Dynamic fragments are an `int` (`approval/ApprovalStore.java:248`), a fixed column name (`ApprovalStore.java:314-319`) and a constant filter (`notification/NotificationController.java:54-60`). LIKE wildcards are not escaped in `supplier/SupplierService.java:55-56` only (`request/RequestLogisticsQueries.java:64` does escape; corrected).
- **Pagination:** main lists capped at 100 (200 in `request/RequestWorkflow.java:78`). Unpaginated: admin/reference lists and `approval/ApprovalStore.java:242` (pending tasks of a user).
- **Per-request cost:** `identity/CurrentUserProvider.java:37-54` loads the user with 2 queries per request (`identity/UserDirectory.java:176-201`), cached for the request only.
- **Audit chain:** `audit/AuditLog.java:52-88` locks one head row per chain (`company:<id>` or `global`) until commit: all audited writes of one company are serialised; sign-in/sign-out events share the `global` chain.
- **Sign-in:** password check runs outside any transaction, with a dummy hash for unknown accounts (`identity/SignInService.java:45-57`).
- **Node-local state:** `identity/LoginThrottle.java:36`, `platform/web/RequestRateLimiter.java:22`, `messaging/InternalMessageStream.java:65`, `request/RequestAdminService.java:73` (preview sessions), HTTP sessions in memory.
- **Scheduled jobs:** approval reminders (1 min), outbox sender (15 s, `UPDLOCK, READPAST` claim, 20 per batch), outbox purge (6 h), stream heartbeat (25 s). No scheduler lock.
- **Timeouts:** no JDBC query timeout and no transaction timeout anywhere except the status probe (`system/JdbcDatabaseProbe.java:112`); driver `lockTimeout=-1`.
- **Frontend:** 117 TS files (20,822 lines), 32 spec files; 35 routes, 34 lazy (`loadComponent`), shell eager. No `innerHTML`/`bypassSecurityTrust`. Return URL validated (`core/auth/safe-return-url.ts`). Storage: last-activity, language, theme, sidebar in `localStorage`; unsaved forms in `sessionStorage` (`core/form-snapshots/form-snapshot-storage.ts`). 190 `subscribe(` against 38 `takeUntilDestroyed`. No polling timers; one `EventSource`. No virtual scrolling. Largest: `request-form.ts` 1,308 lines, `request-admin.ts` 954, `dashboards-page.ts` 754. 11 feature folders without a unit spec.
- **Styles:** 656 logical properties, 7 physical (`features/auth/sign-in.scss:182-244`, decorative orbit). 24 transitions, 22 animations, 12 keyframes; durations and easings tokenised; global reduced-motion rule (`styles.scss:190-198`) plus tokens zeroed (`styles/_tokens.scss:236-243`). 12 distinct breakpoint values, not tokenised. 21 hex colours outside the token file. i18n: 1,494 keys in each of EN/FR/AR.
