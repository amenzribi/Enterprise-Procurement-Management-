# ADR-012 — Internal AI assistant: provider-neutral design and hosting options

| | |
|---|---|
| Status | Accepted for architecture; **production provider pending user approval** |
| Date | 2026-10-31 |
| Sprint | 12 |

## Context

Sprint 12 delivers an internal assistant for buyers and purchasing managers. The product vision is on-premise / private cloud. No external AI provider has been approved. Procurement data must not leave the installation without an explicit decision.

## Decision

1. **Provider-neutral port** (`AssistantModel`) with configuration `app.assistant.mode`:
   - `disabled` (default): API returns unavailable; UI shows disabled.
   - `demo`: deterministic local adapter; responses labelled *“Demo response — not generated by a live AI model.”*
   - `live`: reserved for an approved provider; until configured, behaves as unavailable (no silent external call).

2. **No production provider is selected in this ADR.** Options for later approval:

| Option | Data leaving app | Hosting / hardware | Credentials | Notes |
|---|---|---|---|---|
| A. Self-hosted model endpoint | Stays on private network if endpoint is internal | GPU/CPU capacity, ops ownership | Endpoint URL + optional API key in env | Best alignment with on-prem; language quality TBD |
| B. Approved private/managed service | Prompts/context leave to vendor VPC/region | Vendor SLA; network egress | Vendor key in secret store | Requires DPA, retention, residency review |
| C. Disabled / demo-only | None | None | None | Current default until A or B approved |

3. **Secrets** only via environment / secret store — never in git.

4. **Retrieval** is server-side allowlisted tools only; no model-generated SQL/URLs/code. Authorization runs before any prompt assembly.

5. **Logging**: audit outcome, mode, duration, source IDs — not full prompts/responses by default; never credentials.

## Consequences

- Automated tests and local demo use `demo` only.
- Live-provider quality, pen-test and Arabic/French answer validation remain **blocked**.
- Human messaging and procurement workflows remain usable with assistant disabled.
